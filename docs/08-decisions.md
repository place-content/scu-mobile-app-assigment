# 08. 개발 중 결정 기록

개발하면서 바꾸거나 고민한 내용을 **문제 → 선택지 → 결정 → 이유** 순서로 정리했습니다.
보고서의 "개선 과정", "고민한 점"에 활용할 수 있습니다. (순서는 실제 개발 순서)

---

### 1. UI 방식: Compose → XML
- **문제**: 프로젝트를 처음 만들 때 Android Studio 기본값인 Compose(React처럼 코드로 UI를 그리는 방식) 템플릿이었음
- **선택지**: Compose 유지 / 교안처럼 XML 레이아웃
- **결정**: XML + ViewBinding으로 전환, Compose 관련 파일과 라이브러리 제거
- **이유**: 교안이 XML 레이아웃, RecyclerView, Activity 구조로 설명하므로 교안과 비교·설명하기 쉬움

### 2. 자기만의 기능: 상태 3단계 + 필터
- **문제**: 완료/미완료 두 가지로는 "시작했지만 아직 안 끝난 일"을 구분할 수 없음
- **결정**: `done: Boolean` 대신 `TodoStatus`(할 일 / 진행 중 / 완료) + 상단 필터 버튼(개수 표시)
- **이유**: 팀 과제나 집안일처럼 여러 일을 동시에 할 때 지금 손대고 있는 일만 모아 보기 좋음. 교안의 주요 사용자(소규모 팀, 가족)와도 맞음

### 3. 상태 바꾸기가 번거로움 → 이동 버튼
- **문제**: 처음엔 상태를 바꾸려면 길게 누르기 → 상태 변경 → 선택으로 3단계가 필요했음
- **선택지**
  1. Jira처럼 칸 3개짜리 보드 + 이동 버튼
  2. 보드 + 드래그로 옮기기
  3. 지금 목록 유지 + 항목마다 "다음 단계" 버튼
- **결정**: 3번. 항목 오른쪽에 `시작 ▶` / `완료 ▶`
- **이유**: 변경이 가장 적고, 폰 화면에서 칸 3개나 드래그는 좁고 불편함. 자주 하는 동작이 탭 한 번으로 줄어듦

### 4. `되돌리기` 버튼 제거
- **문제**: 처음엔 완료 항목에 `되돌리기`(완료 → 할 일) 버튼이 있었음
- **결정**: 제거. 완료 항목엔 이동 버튼 없음 (`TodoStatus.next()`가 완료에서 `null`)
- **이유**: 되돌리기는 자주 쓰지 않음. 필요하면 길게 누르기 → 상태 변경으로 가능. 버튼이 줄어 목록이 깔끔해짐

### 5. 체크박스 역할: 완료 표시 → 삭제할 항목 선택
- **문제**: 교안에선 체크박스가 완료/해제였는데, 이동 버튼이 생기면서 완료 처리 수단이 겹침. 그리고 여러 개를 한 번에 지울 방법이 없었음
- **결정**: 체크박스 = 선택. 하나라도 고르면 하단에 `선택 해제` / `선택 삭제 (n)`
- **세부 결정**
  - 필터를 바꾸면 선택 초기화 → 안 보이는 항목이 같이 삭제되는 사고 방지
  - 선택 중 뒤로가기 = 선택 해제 (앱이 닫히지 않게)
  - 선택 상태는 ViewModel에 보관 → 화면 회전해도 유지
  - 일괄 삭제는 `DELETE ... WHERE id IN (...)` 쿼리 한 번
- **영향**: F1.6(완료 표시)은 취소선 + 흐리게로 그대로 충족

### 6. 마감일 입력: 직접 타이핑 → 달력(DatePicker)
- **문제**: `YYYY-MM-DD`를 직접 쳐야 해서 불편하고 틀리기 쉬움
- **결정**: 안드로이드 기본 `DatePickerDialog`. 마감일 칸은 키보드가 안 뜨고 누르면 달력. `지우기` 버튼으로 비우기
- **이유**: 라이브러리 추가 없이 가능하고, 잘못된 날짜가 아예 들어가지 않음. 기존 형식 검증은 안전장치로 유지

### 7. 마감일이 뭔지 모름 → "마감" 라벨
- **문제**: 목록에 `2026-12-01`만 보여서 무슨 날짜인지 알기 어려움
- **결정**: `마감 2026-12-01`로 표시

### 8. 과거 날짜 금지 + 편집 시 예외
- **문제**: 마감일을 과거로 고를 수 있었음
- **결정**: 달력의 `minDate`를 오늘로 → 이전 날짜 선택 불가. 저장할 때도 한 번 더 검사
- **예외**: 편집 화면에서 원래 마감일이 이미 지난 할 일은 그 원래 날짜까지 허용
- **이유**: 예외가 없으면 기한 지난 할 일은 제목 하나 고치려 해도 마감일을 먼저 바꿔야 저장됨. 원래 날짜는 유지하되 더 과거로는 못 가게 함

### 9. 취소 버튼 → 상단 `<` 뒤로 버튼
- **문제**: 하단 `취소` 버튼이 디자인상 어색함
- **선택지**: 편집을 모달/바텀시트로 / 페이지 유지 + 상단 `<`
- **결정**: 페이지 유지 + 상단 바(`MaterialToolbar`)의 `<`. 기기 뒤로가기도 같은 동작
- **이유**: 교안이 추가·편집을 별도 Activity로 설계했기 때문에 구조를 유지. 교안 UC05 "저장/취소 → 복귀"도 그대로 충족. 안드로이드 앱에서 흔한 방식

### 10. 저장·수정 결과 알림 → Toast
- **문제**: 저장해도 목록으로 돌아올 뿐 됐는지 알려주지 않음
- **결정**: "저장했습니다", "수정했습니다" Toast 추가 (삭제·입력 오류 Toast는 원래 있었음)
- **근거**: 교안의 UX 원칙 중 "피드백(Feedback): 사용자의 입력에 즉시 반응"

### 11. 색상
- **결정**: 버튼 등 강조색 `#52677A`, 삭제 관련 `#A6533C`, 눌림 등 진한 톤 `#3E4F5E`
- **방식**: 테마(`themes.xml`)에서 한 번에 지정 → 개별 버튼마다 색을 쓰지 않음. 삭제만 `danger` 색
- **근거**: 교안 UX 원칙 "일관성(Consistency)"과 "오류 방지(Error Prevention)" — 위험한 동작은 다른 색으로 구분

### 12. 뒤로가기로 입력이 사라짐 → "나갈까요?" 확인
- **문제**: 추가·편집 중 실수로 `<`나 기기 뒤로가기를 누르면 길게 쓴 메모도 확인 없이 사라짐
- **선택지**: 항상 확인 / 바뀐 내용이 있을 때만 확인 / 임시 저장
- **결정**: 바뀐 내용이 있을 때만 "저장하지 않은 내용이 있습니다. 나갈까요?" (`나가기` / `계속 작성`)
- **세부 결정**
  - 비교 기준: 추가는 빈 입력, 편집은 DB에서 불러온 원래 값. 앞뒤 공백만 다른 건 변경 아님 (저장할 때도 trim)
  - 원래 값은 화면 회전 후에도 유지 (`onSaveInstanceState`)
  - `<`와 기기 뒤로가기가 같은 함수(`cancelOnBack()`)를 거침
  - 판단은 순수 함수 `TodoInput.hasChanges()`로 분리해 단위 테스트
- **이유**: 매번 묻으면 귀찮고, 아무것도 안 했는데 묻는 건 의미 없음. 교안 UX 원칙 "오류 방지"

### 13. 지난 마감일이 구분되지 않음 → `· 지남` + 경고색
- **문제**: 기한이 지난 할 일도 `마감 2026-11-01`로 똑같이 보여서 놓치기 쉬움
- **결정**: 마감일이 오늘보다 이전이고 완료가 아니면 `마감 2026-11-01 · 지남`, 글자색 `danger`
- **세부 결정**: 오늘이 마감인 건 아직 지난 게 아님. 완료한 항목은 표시하지 않음 (`Todo.isOverdue()`)
- **이유**: 색만 바꾸면 색을 구분하기 어려운 사용자는 모르므로 글자도 함께 붙임. 교안 UX 원칙 "가시성"

### 14. 선택 중 항목 탭 → 선택 토글
- **문제**: 여러 개를 고르다가 체크박스를 살짝 빗나가면 편집 화면으로 넘어감
- **결정**: 하나라도 선택 중이면 항목 탭 = 선택 토글. 선택이 0개면 원래대로 편집 화면
- **이유**: 갤러리·메일 앱 등에서 흔한 방식이라 직관적

### 15. 추가 화면 키보드 → 제목 칸 자동 포커스
- **문제**: `+ 추가`를 눌러도 제목 칸을 한 번 더 눌러야 입력 가능
- **결정**: 제목 칸 `<requestFocus />` + `windowSoftInputMode="stateVisible"`로 바로 키보드 표시
- **비고**: 편집 화면은 내용 확인이 먼저일 수 있어 키보드를 자동으로 띄우지 않음

### 16. 빈 필터 안내, 새 항목 위치
- **빈 필터**: `완료` 필터가 비어도 "할 일이 없습니다"라고 나와 "할 일" 상태와 헷갈림 → "완료 항목이 없습니다"처럼 상태 이름 표시
- **새 항목 위치**: 목록을 내린 상태에서 추가하면 새 항목이 화면 밖 맨 위에 생김 → 방금 추가한 항목이 목록에 나타나면 그 위치로 스크롤

### 17. 코드 리뷰로 다시 고친 것
12~16번을 넣은 뒤 코드 리뷰에서 나온 문제들입니다.

| 문제 | 원인 | 고친 방법 |
|---|---|---|
| 회전하거나 필터·상태를 바꾸면 목록이 맨 위로 튐 | 처음엔 "맨 위에 항목이 끼워지면 스크롤"로 만들었는데, 회전 후 목록을 다시 채울 때나 필터 변경 때도 똑같이 "맨 위에 끼워짐"으로 보임 | Repository가 새 id를 돌려주고, ViewModel이 "방금 추가한 id"를 기억. 그 id가 목록에 나타날 때만 한 번 스크롤 (`takeJustAddedPosition()`). 필터를 바꾸면 비움 |
| 자정이 지나도 `· 지남`이 안 붙음 | 줄을 그릴 때 오늘 날짜로 계산했지만, 목록 데이터는 그대로라 DiffUtil이 다시 그리지 않음 | `TodoRow`에 `overdue` 값을 넣고, 화면이 보이는 동안 1분마다 오늘 날짜를 ViewModel에 넣어 줌 → 날짜가 바뀌면 해당 줄만 다시 그림 |
| 편집 화면을 열자마자 회전하면 빈 화면, 그대로 저장하면 메모·마감일이 지워짐 (원래 있던 버그) | 회전 후엔 DB를 다시 읽지 않았는데, 읽기 전에 회전하면 저장해 둔 값도 없음 | 저장해 둔 원래 값이 없으면 다시 불러옴. 불러오기 전엔 저장 버튼이 동작하지 않음 |
| "나갈까요?" 창이 떠 있을 때 회전하면 창이 사라짐 | 일반 `AlertDialog`는 회전 후 다시 만들어지지 않음 | `DialogFragment`(`DiscardChangesDialog`)로 바꾸고, 결과는 Fragment Result로 받음 |
| 선택 중 탭 로직에 테스트 없음 | ViewModel은 Room에 의존해서 단위 테스트가 어려움 | 판단을 순수 함수 `TodoSelection.onTap()`으로 빼서 테스트 |

### 18. 추가 버튼 위치, 빈 목록 문구, 저장 버튼 비활성화
- **추가 버튼 위치**
  - 문제: 하단 가득 찬 `+ 추가` 버튼이 디자인상 무거워 보임
  - 결정: 화면 제목 오른쪽으로 이동. 하단은 선택 중일 때만 `선택 해제` / `선택 삭제 (n)` (`selectionBar`)
  - 이유: 추가와 선택 삭제가 서로 자리를 바꾸지 않아 버튼이 갑자기 사라지는 일이 없음
- **빈 목록 문구**: "할 일이 없습니다" → "할 일이 등록되지 않았습니다" (아직 아무것도 추가하지 않은 상태라는 걸 분명히)
- **저장 버튼 비활성화 + 빈 필수 칸 표시**
  - 문제: 제목 없이 저장을 눌러야 비로소 Toast로 알 수 있음
  - 결정: 추가 화면에서 제목이 비어 있으면 저장 버튼 비활성. 비활성 버튼을 누르면 제목 칸 밑줄을 `danger` 색으로 바꾸고 아래에 "제목을 입력하세요". 제목을 채우면 바로 원래대로
  - 구현: 안드로이드는 비활성 버튼의 클릭을 전달하지 않으므로 버튼을 `saveButtonArea`(FrameLayout)로 감싸고, 비활성일 땐 버튼의 `isClickable`도 꺼서 터치가 감싼 영역으로 넘어가게 함. 판단은 `TodoInput.canSave()`
  - 디자인: `TextInputLayout`은 다른 입력칸과 모양이 달라져서 쓰지 않고, 기존 입력칸의 밑줄 색만 바꿈. 힌트에 `(필수)` 표시 (메모·마감일은 원래 `(선택)`)
  - 범위: 추가 화면만. 편집 화면은 기존처럼 저장 시 Toast

### 19. 필터: 라디오 버튼 → 알약 모양 칩
- **문제**: 기본 라디오 버튼(동그라미 + 글자)이 요즘 앱에 비해 투박해 보임
- **선택지**: 라디오 유지 / 탭(밑줄) / 세그먼트 컨트롤(회색 바 안에서 흰 칸이 움직임) / 알약 모양 칩
- **결정**: Material `ChipGroup` + `Chip` 알약 모양 (토스 같은 국내 금융 앱에서 흔한 스타일)
  - 선택 안 됨: 연한 회색 배경(`chip_bg`) + 회색 글자(`chip_text`)
  - 선택됨: 강조색(`primary`) 배경 + 흰 굵은 글자. 테두리·체크 아이콘 없음
  - `singleSelection` + `selectionRequired` → 라디오처럼 하나만, 다시 눌러도 해제 안 됨
- **이유**: 라이브러리 추가 없이 이미 쓰는 Material 위젯으로 가능. 칩 개수가 늘어도 가로 스크롤로 대응. 색은 새로 정하지 않고 기존 강조색 사용
- **세부**: 스타일은 `themes.xml`의 `Widget.Todo.FilterChip` 하나로 모음. 글자 굵기는 Chip이 `textAppearance`로 받아서 별도 스타일. 회색이 다크 모드에서 튀지 않도록 `values-night/colors.xml`에 어두운 톤

### 20. 색상을 밝게
- **문제**: 회청색 `#52677A`와 갈색 계열 `#A6533C`가 전체적으로 어둡고 탁해 보임
- **결정**: 맑은 파랑과 선명한 빨강으로 변경 (11번 색상을 대체)

| 이름 | 이전 | 변경 |
|---|---|---|
| `primary` | `#52677A` | `#2B72D9` |
| `primary_dark` | `#3E4F5E` | `#1F5FBF` |
| `danger` | `#A6533C` | `#CF4436` |

- **기준**: 더 밝게 하되 흰 배경·흰 글자와의 명도 대비 4.5:1 이상(WCAG AA) 유지. 버튼 위 흰 글자, `· 지남`·"제목을 입력하세요" 같은 작은 빨간 글자도 읽혀야 함 (`primary` 4.65, `danger` 4.63)
- **방식**: `colors.xml` 값만 바꾸면 테마를 통해 버튼·칩·체크박스·삭제 표시가 한 번에 바뀜 (11번에서 테마로 일괄 지정해 둔 덕분)

### 21. 베이스 컬러 하나: 세이지 그린

### 22. 선택 바를 하단 → 상단 헤더로
- **문제**: 18번에서 선택 중일 때만 하단에 `선택 해제` / `선택 삭제 (n)`을 띄웠는데, 체크박스를 누른 손에서 멀고 갑자기 생긴 바가 목록을 가림
- **결정**: 선택 중이면 상단 헤더 `할 일 목록 [+ 추가]` 자리가 `n개 선택됨 · 선택 해제 · [삭제]`로 바뀜 (지메일·사진 앱의 선택 모드와 같은 방식)
- **세부**
  - `headerDefault`와 `selectionBar`를 같은 `FrameLayout`(최소 높이 56dp)에 겹쳐 두고 보이기만 전환 → 칩과 목록 위치가 움직이지 않음
  - 개수는 버튼 글자(`선택 삭제 (n)`) 대신 왼쪽 큰 글자 `n개 선택됨`으로. 버튼은 `삭제` 한 단어
  - `선택 해제`는 테두리 없는 글자 버튼, `삭제`만 `danger` 색 채운 버튼 → 위험한 동작만 눈에 띄게
  - 선택 중엔 `+ 추가`가 잠시 가려짐 (선택을 마치거나 뒤로가기를 누르면 다시 보임)

### 23. 정적 분석 detekt 추가
- **문제**: ktlint는 모양(들여쓰기, 줄 길이)만 보고, 매직 넘버·복잡도·잠재 버그 같은 코드 품질은 검사하지 않음
- **결정**: detekt 1.23.8 (안정 버전) 추가. ktlint와 같은 방식으로 루트 `build.gradle.kts`에 CLI 작업(`./gradlew detekt`)으로 연결
- **규칙**: `config/detekt/detekt.yml`. detekt 기본 규칙을 그대로 쓰고 바꾸는 것만 적음
  - 한 줄 120자 (`.editorconfig`·ktlint와 같게)
  - 클래스당 함수 15개까지 (ViewModel은 화면 이벤트마다 짧은 함수가 있는 구조라 기본 11개는 빡빡함)
- **처음 실행 결과 8건 → 0건**. 설정으로 끄기보다 코드를 고치는 쪽을 우선함

| 지적 | 고친 방법 |
|---|---|
| 매직 넘버 (`3`, `0.5f`, 배열 `[3]`) | `DUE_PARTS`, `DONE_ALPHA` 상수. 여백은 배열 대신 변수 4개 |
| 4개짜리 구조 분해 (`val (a, b, c, d) = ...`) | `draft.title`처럼 이름으로 사용. 회전 대비 저장도 순서에 의존하는 배열 대신 키가 있는 `Bundle` |
| return이 너무 많음 (`validate()` 5개, `parseDue()` 3개) | `validate()`는 `when` 하나로 → 검사 순서가 한눈에 보임. `parseDue()`도 return 하나 |
| ViewModel 함수 12개 | 설정으로 기준 15개 (위 이유) |

- **함께 정리**: 루트 `build.gradle.kts`의 `by configurations.creating`이 Gradle 9.6에서 deprecated → `configurations.create(...)`로 변경

### 24. CI (GitHub Actions)
- **문제**: 검사 다섯 개(빌드 · 단위 테스트 · 린트 · ktlint · detekt)를 사람이 로컬에서 직접 돌려야 해서, 잊고 푸시하면 깨진 코드가 올라갈 수 있음
- **결정**: `.github/workflows/ci.yml` 하나. `main`·`develop` 푸시와 모든 PR에서 로컬과 같은 다섯 검사를 실행 (코드 검증만, 배포는 하지 않음)
- **세부**
  - JDK 25: `gradle/gradle-daemon-jvm.properties`의 `toolchainVersion`과 맞춤
  - `gradle/actions/setup-gradle`로 의존성 캐시 → 두 번째 실행부터 빠름
  - 검사마다 단계를 나눠서 어디서 실패했는지 Actions 화면에서 바로 보임
  - 실패하면 리포트(`lint-results`, `detekt.html`, 테스트 결과)를 Artifacts로 7일간 보관
  - 같은 브랜치에 연달아 푸시하면 이전 실행은 취소
