# 08. 개발 중 결정 기록

개발하면서 바꾸거나 고민한 내용을 **문제 → 선택지 → 결정 → 이유** 순서로 정리했습니다.
보고서의 "개선 과정", "고민한 점"에 활용할 수 있습니다. (순서는 실제 개발 순서)

---

### 1. UI 방식: Compose → XML
- **문제**: 프로젝트를 처음 만들 때 Android Studio 기본값인 Compose(React처럼 코드로 UI를 그리는 방식) 템플릿이었음
- **선택지**: Compose 유지 / 교안처럼 XML 레이아웃
- **결정**: XML + ViewBinding으로 전환, Compose 관련 파일과 라이브러리 제거
- **이유**: 교안이 XML 레이아웃, RecyclerView, Activity 구조로 설명하므로 교안과 비교·설명하기 쉬움

### 2. 자기만의 기능: 상태 3단계 + 필터
- **문제**: 완료/미완료 두 가지로는 "시작했지만 아직 안 끝난 일"을 구분할 수 없음
- **결정**: `done: Boolean` 대신 `TodoStatus`(할 일 / 진행 중 / 완료) + 상단 필터 버튼(개수 표시)
- **이유**: 팀 과제나 집안일처럼 여러 일을 동시에 할 때 지금 손대고 있는 일만 모아 보기 좋음. 교안의 주요 사용자(소규모 팀, 가족)와도 맞음

### 3. 상태 바꾸기가 번거로움 → 이동 버튼
- **문제**: 처음엔 상태를 바꾸려면 길게 누르기 → 상태 변경 → 선택으로 3단계가 필요했음
- **선택지**
  1. Jira처럼 칸 3개짜리 보드 + 이동 버튼
  2. 보드 + 드래그로 옮기기
  3. 지금 목록 유지 + 항목마다 "다음 단계" 버튼
- **결정**: 3번. 항목 오른쪽에 `시작 ▶` / `완료 ▶`
- **이유**: 변경이 가장 적고, 폰 화면에서 칸 3개나 드래그는 좁고 불편함. 자주 하는 동작이 탭 한 번으로 줄어듦

### 4. `되돌리기` 버튼 제거
- **문제**: 처음엔 완료 항목에 `되돌리기`(완료 → 할 일) 버튼이 있었음
- **결정**: 제거. 완료 항목엔 이동 버튼 없음 (`TodoStatus.next()`가 완료에서 `null`)
- **이유**: 되돌리기는 자주 쓰지 않음. 필요하면 길게 누르기 → 상태 변경으로 가능. 버튼이 줄어 목록이 깔끔해짐

### 5. 체크박스 역할: 완료 표시 → 삭제할 항목 선택
- **문제**: 교안에선 체크박스가 완료/해제였는데, 이동 버튼이 생기면서 완료 처리 수단이 겹침. 그리고 여러 개를 한 번에 지울 방법이 없었음
- **결정**: 체크박스 = 선택. 하나라도 고르면 하단에 `선택 해제` / `선택 삭제 (n)`
- **세부 결정**
  - 필터를 바꾸면 선택 초기화 → 안 보이는 항목이 같이 삭제되는 사고 방지
  - 선택 중 뒤로가기 = 선택 해제 (앱이 닫히지 않게)
  - 선택 상태는 ViewModel에 보관 → 화면 회전해도 유지
  - 일괄 삭제는 `DELETE ... WHERE id IN (...)` 쿼리 한 번
- **영향**: F1.6(완료 표시)은 취소선 + 흐리게로 그대로 충족

### 6. 마감일 입력: 직접 타이핑 → 달력(DatePicker)
- **문제**: `YYYY-MM-DD`를 직접 쳐야 해서 불편하고 틀리기 쉬움
- **결정**: 안드로이드 기본 `DatePickerDialog`. 마감일 칸은 키보드가 안 뜨고 누르면 달력. `지우기` 버튼으로 비우기
- **이유**: 라이브러리 추가 없이 가능하고, 잘못된 날짜가 아예 들어가지 않음. 기존 형식 검증은 안전장치로 유지

### 7. 마감일이 뭔지 모름 → "마감" 라벨
- **문제**: 목록에 `2026-12-01`만 보여서 무슨 날짜인지 알기 어려움
- **결정**: `마감 2026-12-01`로 표시

### 8. 과거 날짜 금지 + 편집 시 예외
- **문제**: 마감일을 과거로 고를 수 있었음
- **결정**: 달력의 `minDate`를 오늘로 → 이전 날짜 선택 불가. 저장할 때도 한 번 더 검사
- **예외**: 편집 화면에서 원래 마감일이 이미 지난 할 일은 그 원래 날짜까지 허용
- **이유**: 예외가 없으면 기한 지난 할 일은 제목 하나 고치려 해도 마감일을 먼저 바꿔야 저장됨. 원래 날짜는 유지하되 더 과거로는 못 가게 함

### 9. 취소 버튼 → 상단 `<` 뒤로 버튼
- **문제**: 하단 `취소` 버튼이 디자인상 어색함
- **선택지**: 편집을 모달/바텀시트로 / 페이지 유지 + 상단 `<`
- **결정**: 페이지 유지 + 상단 바(`MaterialToolbar`)의 `<`. 기기 뒤로가기도 같은 동작
- **이유**: 교안이 추가·편집을 별도 Activity로 설계했기 때문에 구조를 유지. 교안 UC05 "저장/취소 → 복귀"도 그대로 충족. 안드로이드 앱에서 흔한 방식

### 10. 저장·수정 결과 알림 → Toast
- **문제**: 저장해도 목록으로 돌아올 뿐 됐는지 알려주지 않음
- **결정**: "저장했습니다", "수정했습니다" Toast 추가 (삭제·입력 오류 Toast는 원래 있었음)
- **근거**: 교안의 UX 원칙 중 "피드백(Feedback): 사용자의 입력에 즉시 반응"

### 11. 색상
- **결정**: 버튼 등 강조색 `#52677A`, 삭제 관련 `#A6533C`, 눌림 등 진한 톤 `#3E4F5E`
- **방식**: 테마(`themes.xml`)에서 한 번에 지정 → 개별 버튼마다 색을 쓰지 않음. 삭제만 `danger` 색
- **근거**: 교안 UX 원칙 "일관성(Consistency)"과 "오류 방지(Error Prevention)" — 위험한 동작은 다른 색으로 구분

---

## 교안 UX 원칙과의 대응
| 교안 원칙 | 이 앱에서 |
|---|---|
| 일관성 | 색을 테마에서 일괄 지정, 삭제는 항상 같은 색과 같은 확인 창 |
| 피드백 | 저장·수정·삭제·오류 Toast, 필터 개수 실시간 갱신 |
| 가시성 | 상태별 표시(`[진행 중]`, 취소선), 선택 개수 `선택 삭제 (n)` |
| 직관성 | `+ 추가`, `시작 ▶`/`완료 ▶`, 상단 `<` 뒤로 |
| 오류 방지 | 삭제 확인 창, 빈 제목 차단, 달력으로 날짜 입력, 과거 날짜 금지, 필터 변경 시 선택 초기화 |
