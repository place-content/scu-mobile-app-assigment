# 문서 목차

할 일 관리 앱(모바일앱제작프로그래밍 과제)의 설계·개발 문서입니다.
Android 용어는 처음 나올 때 React/Next 비유를 같이 적었습니다.

| 문서 | 내용 | 이럴 때 읽기 |
|---|---|---|
| [01-overview.md](01-overview.md) | 과제 요구사항, 앱 소개, 기능 목록, 교안과 달라진 점 | 앱이 뭘 하는지 한눈에 볼 때 |
| [02-user-guide.md](02-user-guide.md) | 화면별 구성과 버튼별 동작 | 앱 사용법을 정확히 알고 싶을 때 |
| [03-user-flow.md](03-user-flow.md) | 사용 흐름(UC01~UC07), 화면 이동도, 상태 전이도 | 보고서의 "사용 흐름/UI 설계" 부분 |
| [04-architecture.md](04-architecture.md) | MVVM 구조, 계층별 역할, 데이터 흐름 | 보고서의 "앱 구조 설계" 부분 |
| [05-data-model.md](05-data-model.md) | DB 테이블, 상태값, 입력 검증 규칙 | 데이터가 어떻게 저장되는지 볼 때 |
| [06-dev-rules.md](06-dev-rules.md) | 폴더 구조, 이름 규칙, 리소스 규칙, 빌드/테스트 명령 | 코드를 고치거나 기능을 추가할 때 |
| [07-testing.md](07-testing.md) | 단위 테스트 목록, 수동 테스트 체크리스트 | 보고서의 "테스트 및 검증" 부분 |
| [08-decisions.md](08-decisions.md) | 개발 중 바뀐 결정과 그 이유 | 보고서의 "개선 과정/고민한 점" 부분 |
| [09-report-guide.md](09-report-guide.md) | 보고서 목차 제안, 알려진 한계 | 보고서를 쓰기 시작할 때 |

## 추천 읽는 순서
1. `01-overview` → `02-user-guide`로 앱이 뭘 하는지 파악
2. `03-user-flow` → `04-architecture`로 화면과 코드 구조 이해
3. 보고서 쓸 때 `09-report-guide`를 뼈대로 두고 나머지 문서에서 내용을 가져오기
